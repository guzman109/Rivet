# Rivet documentation site

The documentation uses TypeScript, Svelte 5, SvelteKit 3, and mdsvex. Bun 1.4.2 runs the development server, build, and checks. Wrangler runs the built site in Cloudflare's local runtime and deploys it as Worker static assets. Wrangler uses Node.js (the local validation used Node 26); use a supported Node LTS in CI. No Deno installation is needed.

## Appearance

The interface uses [Catppuccin Latte and Mocha](https://catppuccin.com/palette/)
with maroon UI accents and neutral surfaces. Syntax highlighting maps
[Catppuccin/nvim's highlight groups](https://github.com/catppuccin/nvim/tree/main/lua/catppuccin/groups)
to mdsvex's Prism tokens using the exact upstream Latte and Mocha palette values
in `src/lib/catppuccin.css`. Functions are blue, types yellow, strings green,
numbers and booleans peach, operators sky, and comments italic. Token boundaries
come from Prism rather than Neovim's Tree-sitter or LSP, so semantic details can
differ from the editor. Code uses each flavor's base background. Dark mode
follows the operating system; the UI keeps its darker Latte text accents.

Space Grotesk and Space Mono are bundled locally, with a serif accent in the
homepage headline. The responsive docs shell includes local keyboard search,
mobile navigation, copyable code, and article navigation. The homepage offers
Neovim and terminal setup examples.

Font license notices ship with the static site:
[Space Grotesk](static/licenses/space-grotesk.txt) and
[Space Mono](static/licenses/space-mono.txt). The
[Catppuccin MIT notice](static/licenses/catppuccin-nvim.txt) also ships with the site.

## Develop

Run commands from this `docs/` directory:

```sh
bun install --frozen-lockfile
bun run dev
```

Open the local URL printed by Vite. It listens on `127.0.0.1` and gives fast updates while editing. Run `bun run preview` for the production build served by Wrangler at `http://127.0.0.1:8787`.

Exact dependency versions live in `package.json`; commit `bun.lock` and install with `--frozen-lockfile` to reproduce the complete graph. `node_modules/`, `.svelte-kit/`, `build/`, and `.wrangler/` are local artifacts ignored by Git.

## Author pages

Add or edit `.svx` files in `src/content/`. Each file combines Markdown, fenced
code samples, and optional Svelte components. Keep its frontmatter consistent
with neighboring pages so navigation and search can find it. The route and
navigation code lives under `src/routes/` and `src/lib/`.

```yaml
---
title: Page title
description: A short description of what the reader will learn.
section: Guides
order: 20
updated: '2026-10-09'
---
```

Use `Start here`, `Guides`, or `Reference` for `section`; give each page a
stable, unique `order` within that section. Navigation sorts by section first,
then by order; the same sequence drives the sidebar and previous/next links.
The filename becomes its `/docs/<filename>/` URL. The
metadata plugin reads frontmatter separately so navigation does not import every
page's Svelte component.

Use one page title in the site layout and start article sections at `##`.
Heading IDs are generated by `rehype-slug`; the table of contents uses
`github-slugger` to match them. Fenced code uses mdsvex's Prism highlighter with
a JSON string wrapper that preserves copyable backslashes and line breaks. Use
descriptive image alt text, link labels, and section titles. Use Svelte
components for interactive examples and TypeScript for their logic.

SvelteKit 3 configuration lives in `vite.config.ts`; it does not use
`svelte.config.js`. Project source uses relative imports with explicit file
extensions. `package.json` also provides an optional `#lib/...` alias.

## Check and build

```sh
bun run check
bun run lint
bun run test:highlight
bun run build
bun run check:docs
bun run test:cloudflare
bun run cf:check
bun run preview
```

`check` synchronizes generated SvelteKit types and runs strict Svelte/TypeScript
diagnostics, including warnings. `build` prerenders the site into `build/` using
the static adapter. `check:docs` validates documentation metadata, links,
code-fence preservation, and the rendered previous/next reading sequence.
`test:cloudflare` starts a separate local Wrangler process, checks every guide, canonical redirects, real 404 responses, MIME types, caching, bundled fonts, and license delivery, then stops that process. `cf:check` performs a deployment dry run. Neither publishes anything. `preview` serves the built site through Wrangler until you stop it.

`test:highlight` verifies that highlighted shell, C++, Lua, and CMake samples
preserve their original characters, including escapes and line continuations.

The Neovim guide includes actual editor UI captures in `static/images/`. To
refresh them, run `python3 docs/scripts/capture-neovim.py` from the repository
root with Neovim, Lua, CMake, Ninja, a C++17 compiler, Pillow, and msgpack
available. The script attaches to Neovim's UI grid, creates and builds a
temporary CPU starter, captures its real CTest output, and removes that fixture.
It uses Menlo on macOS; set `RIVET_CAPTURE_FONT` to another monospace font path
on other systems. `RIVET_CAPTURE_LIBS` optionally supplies a Python dependency
directory without modifying the global environment.

`bun run format` formats the site and TypeScript tooling with Prettier and its
Svelte plugin, using the same tabs, single quotes, and 100-column convention as
`orbit-book`. `bun run lint` checks formatting without changing files. `.svx`
content is excluded so formatting does not alter authored code samples or mdsvex
markup. The documentation audit checks those pages separately. The strict
TypeScript check also includes the Vite metadata loader and formatter config.

## Deploy to Cloudflare

The existing static adapter produces prerendered HTML. `wrangler.jsonc` points to `build/`; no server-side adapter or Worker code is needed for this site. Cloudflare normalizes document URLs to trailing slashes, serves `404.html` with a 404 status for unknown routes, and applies the rules in `static/_headers`.

```sh
bun install --frozen-lockfile
bun run verify
bun run cf:check
bun x --no-install wrangler login
bun run deploy
```

`deploy` runs verification again before uploading. Configure the intended Cloudflare account when prompted (or set its account ID in the Wrangler configuration). The Worker name is `rivet-docs`; the first deployment can use its `workers.dev` address. Attach a custom domain in Cloudflare after checking that deployment. No domain or account is assumed in this checkout. Never commit API tokens, `.dev.vars`, or `.env` files. For unattended deployment, provide `CLOUDFLARE_ACCOUNT_ID` and a scoped `CLOUDFLARE_API_TOKEN` through the CI secret store.

The configuration targets the domain root. A URL subdirectory requires coordinated SvelteKit base-path and content-link changes followed by both audits. Only `build/` is uploaded; dependencies and source files stay local.

### Deploy from GitHub Actions

The repository's `Checks` workflow includes a final **Deploy docs to Cloudflare** job. It runs after formatting, types, Linux, macOS, and docs checks pass for a push to `main`. CI saves the already validated `build/` directory as a commit-specific artifact; deployment downloads that artifact and uses the same commit's pinned Wrangler configuration. Pull requests and other branches do not deploy. Production deployments are serialized, and a run skips deployment if its commit is no longer the head of `main`.

Set these repository secrets at **GitHub → Rivet → Settings → Secrets and variables → Actions → New repository secret**:

| Secret                  | Value                                                                                                 |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `CLOUDFLARE_ACCOUNT_ID` | The Cloudflare account that owns `rivet-docs`.                                                        |
| `CLOUDFLARE_API_TOKEN`  | A Cloudflare token using the **Edit Cloudflare Workers** permission template, scoped to that account. |

Cloudflare documents [GitHub Actions authentication](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/) and [finding an account ID](https://developers.cloudflare.com/fundamentals/account/find-account-and-zone-ids/). Enter credentials through GitHub's secret fields; the workflow never prints their values.

After adding the secrets, push to `main`, or select **Actions → Checks → Run workflow → main**. A manual run performs all checks before deployment. Automatic runs without credentials skip publishing and list the missing secret names in the job summary; manual runs without credentials fail with the same setup instructions. The deployed Worker is named `rivet-docs` and uses its `workers.dev` address or an attached custom domain.

If you connected this repository directly to Cloudflare Workers Builds, disconnect that connection in **rivet-docs → Settings → Builds** when using the GitHub Action, so the two systems do not compete to publish the site. Disconnecting Builds leaves the existing deployment online. No local Wrangler login or GitHub build-command fields are needed for the GitHub Action.

For a deliberate dependency update, edit the exact versions in `package.json`, run `bun install`, then `bun run verify` and `bun run cf:check`. Review `bun.lock` with those edits. TypeScript remains on the compatible 6.x line.
